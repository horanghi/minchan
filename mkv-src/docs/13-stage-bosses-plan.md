# 13. 스테이지별 절지류 보스 기획 — AF-3

## 개요와 적용 범위

AF-3의 방향은 “각 stage 별로 보스가 개미·거미·전갈 등(절지류)으로 구성되고 공격 패턴도 다르게”이다. 현재 `src/game/world.ts:286`은 스테이지 종류를 확인하지 않고 `cairn: createCairn(...)`을 생성한다. [04-stages.md §4.1 구현 현황](04-stages.md)도 “보스는 다섯 판 모두 캐른”이라고 명시한다.

**S1 캐른은 구현 완료, 유지한다.** S2 불타는 마령촌에는 개미, S3 얼어붙은 종루에는 거미, S4 속삭이는 늪에는 전갈, S5 눈먼 갱도에는 지네 보스를 새로 제안한다. 외형뿐 아니라 각각 진로 압박, 박자 판독, 국소 봉쇄, 방향 예고를 주된 과제로 삼는다. 이 문서는 기획만 추가하며 기존 문서·코드·JSON은 수정하지 않는다.

## 세계관 연결

01 §1.4의 확정 설정은 왕국의 역병이 왕가의 죄에서 비롯되었고, 마령촌은 아스모데우스가 지배하며, 전체가 루시안의 환영이라는 것이다. **신규 서사 제안**으로, 사람의 생활 공간을 함께 차지하던 작은 절지류를 그 환영이 폐허의 기능에 맞춰 거대하게 재구성했다고 설정한다. 불탄 집 아래를 파던 개미는 잿더미를 운반하는 화로가 되고, 종루의 거미줄은 얼어붙은 종의 진동을 전달하며, 늪의 전갈은 썩은 수액을 독침으로 모으고, 갱도의 지네는 버려진 레일을 몸마디처럼 이어 움직인다. 이는 현실 생물의 생태나 역병의 전파 경로에 관한 주장이 아니다. 절지류가 역병의 원인이라는 설정도 추가하지 않는다.

플레이어에게는 01의 “컷신 없음”을 따라 불탄 왕가 문장을 물고 있는 개미, 종을 매단 실, 독빛이 비치는 꼬리, 벽을 차례로 두드리는 다리로 관계를 보여준다. 대사나 설명문을 읽어야 패턴을 이해하는 구조로 만들지 않는다. 1회차에 루시안의 정체를 직접 공개하지 않고, 환경과 생물이 같은 재질로 무너지는 격파 연출로 환영의 성질만 암시한다.

좌표는 논리 px이다. 근접 리치는 **바라보는 쪽 본체 가장자리부터** 잰다. 원거리 겨냥 상한은 캐른처럼 본체 중심에서 목표까지 잰다. 표의 “맡는 거리”는 근접/중거리/원거리에서 하는 역할이며, 옆 열의 AABB가 실제 피해 범위다. 실루엣·다리 전체를 자동으로 피해 판정으로 사용하지 않는다.

“전역 지목”은 화면 전체를 피해로 채운다는 뜻이 아니다. 보스룸의 플레이어 위치를 거리 제한 없이 지목하되 **플레이어 화면 안에 고정 표식을 먼저 표시하고 그 국소 영역에만 공격**한다. 보스가 화면 밖이라도 표식만으로 실행 시점을 알 수 있어야 한다. 판정이 생기는 곳, 탈출 방향과 착지점이 화면에 함께 들어오지 않으면 실행을 늦춘다. 이는 캐른의 거리 무관 지진을 가시성 조건과 함께 사용하는 신규 제안이다.

### 3페이즈와 패턴 순환

신규 보스 전부 5패턴 A~E를 쓴다. P1은 A·B·C, P2는 D 추가, P3는 E 추가다. HP 전환은 05 §5.3의 60%·25%를 그대로 따른다. 정확히 경계 HP가 되면 다음 페이즈이며 HP 0은 사망이다.

**신규 가중치 순환 제안:** P1은 `A → B → C`, P2는 `A → B → C → D → C`, P3는 `A → B → C → D → C → E → C`를 반복한다. A·B·D·E의 가중치는 각 1, C는 페이즈별 1·2·3이다. 이 숫자는 캐른의 균등 난수 추첨을 05 §5.3의 가중치 순환으로 바꾸기 위한 제안이다. 동일 패턴 연속은 이 순서에서는 발생하지 않으므로 최대 2회 규칙을 충족한다. C를 모든 페이즈에 넣어 원거리 정지 공략을 막는다.

페이즈는 피격 즉시 계산하되 이미 예고한 공격은 바꾸지 않는다. 다음 패턴을 고를 때 새 순환표를 적용하고, 초기화 위치는 C로 정한다. 근거: 캐른 `damageCairn`은 `phaseFor(hp)`를 갱신하지만 사망 외에는 현재 `state`를 보존한다. 전환 직후 C부터 시작하는 것은 신규 제안이며 선행 시간은 전부 다시 제공한다.

### “안전지대 없음”과 확정 회피는 함께 지킨다

05 §5.4가 금지하는 것은 “거기 서서 던지기만 하는 것이 최적해”인 **영구 안전 위치**다. 매 공격에 남는 일시적인 회피 공간은 반드시 있어야 한다. 아래 보스별 검증표는 허용한 각 페이즈 조합과 추가 패턴의 연결을 검토한다.

허용 순환에서 발생하는 모든 연결 `A→B, B→C, C→A, C→D, D→C, C→E, E→C`에 공통으로 다음을 적용한다. 공격 상자·투사체·봉쇄가 끝난 뒤 회복과 대기, 다음 선행을 준다. **서로 다른 패턴의 유해 판정 중첩은 허용하지 않는다.** B의 포물선이 남았다고 회복 타이머만 보고 C를 방출해서는 안 된다. E 내부의 순차 공격도 각각 예고하며 앞 판정이 끝난 뒤 다음 판정을 낸다. 이 제한이 표에 없는 임의 조합을 금지한다.

그레이박스에서 다음 두 검사를 별도로 통과해야 한다.

- 정지 검사: 서기와 웅크리기, 본체 양쪽, 벽 끝, 보스에게 모든 무기로 피해를 줄 수 있는 위치를 검사한다. 각 페이즈 전체 순환에 대해 어떤 유해 상자도 닿지 않는 위치가 있으면 실패다. 캐른 `bossRange.test.ts`의 거리 30·45·60·70·85·100·120·150px와 지진 300px 검사를 비교 사례로 삼되, 그 표본만으로 전체 공간을 검증했다고 하지 않는다.
- 이동 검사: 동일 상태·동일 예고에서 시작해 걷기·웅크리기·고정 점프 중 적어도 하나로 노히트 회피 가능해야 한다. 플레이어의 이동 가속, 이미 공중인 경우, 본체 접촉, 벽, 투사체 비행 중 몸통 통과까지 포함한다. HP나 피격 무적 72f로 강제 피해를 버티는 경로는 통과로 세지 않는다.

표의 판정은 **설계상 조건부 충족, 구현 실측 전**이다. 공통 C가 있는 순환 전체에는 정지 피난처를 두지 않지만, A나 B만 떼어 놓으면 사거리 밖이나 투척 사이가 안전하다. 이를 모든 단일 공격이 모든 위치를 때려야 한다는 요구로 바꾸지 않는다.

### 플레이어 제약·공정성·밀도

모든 패턴의 목표 위치와 방향은 선행 시작에 고정하고, 표식이 나온 뒤 플레이어를 따라 이동시키지 않는다. 캐른 `stepCairn`은 매 틱 `facing`을 갱신하므로 신규 보스는 별도 `attackFacing`·`targetSnapshot`을 저장해야 한다. 두 필드는 **현재 캐른에 없는 신규 제안 필드**다.

점프 중 궤도 변경, 가변 점프, 대각선 공격, 공중 감속을 요구하지 않는다. 빙판·감속 수위·암전·지형 붕괴를 신규 보스의 필수 조건으로 두지 않는다. 불·독은 이 기획에서 일반 피격 위험물이며, 닿으면 즉사하는 `^` 타일로 생성하지 않는다. 보스룸 밖 위험 타일 위로 퇴각하는 것을 확정 회피로 세지 않는다.

벽·본체로 한쪽 길이 막히면 표식 배치 전에 방 안쪽 회피 길을 남긴다. 지목 지점에 선 플레이어가 몸 전체로 빠져나갈 틈이 없으면 외곽 보조 판정을 생략하고 중앙 판정만 유지한다. 표식을 낸 뒤 좌표를 벽 쪽으로 보정하지 않는다. 이는 G4의 간격을 경계에서도 보전하기 위한 신규 제안이다. C는 중앙 판정을 남기므로 이 예외로 정지 안전지대가 생기지는 않는다.

신규 보스는 **잡몹 소환 0**, 보스 1체를 제안한다. 캐른 지진의 좀비 3마리는 복사하지 않는다. 보스전 동시 적 수는 보스를 보수적으로 포함해 S2·S3 최대 5, S4 최대 6, S5 최대 7 이하로 검사한다. 05 §5.5의 평균치는 일반 진행 구간 기준으로 두고 보스룸에 그 수만큼 적을 채우지 않는다. 기존 적이 입구에서 따라온 경우도 상한과 회피 경로에 포함한다. 공격에 방해되는 잡몹이 회피 길을 점유하면 해당 패턴의 선행 진입을 보류한다.

각 보스의 위험물/파츠 최대 동시 유해 상자는 아래에 명시한다. G7의 전역 위험물 12개보다 낮으며, 수량뿐 아니라 화면의 표식과 잔상 가독성도 검증한다. 월드가 방출물을 상한에서 조용히 버릴 수 있으므로 **필요한 자리를 확보한 뒤 예고**한다. 예고만 하고 공격이 사라지는 상태를 밀도 제어라고 인정하지 않는다.

### 목표 시간의 해석과 검증 한계

전 보스의 목표는 05 §5.3대로 **첫 도전 3~5분, 숙련 60~90초**다. 신규 측정 규칙으로 보스가 깨어난 시점부터 격파까지의 조작 가능 시간을 기록하고, 사망한 도전은 성공 시간과 구분해 별도로 남긴다. HP만으로 이 시간을 보장했다고 하지 않는다. 02의 동시 발사 제한 2발(단검 3발), 무기별 공격 궤도, 약점 명중률, 공격 기회를 실측해야 한다. 시간 맞추기용 강제 무적·HP 재생·전환 컷신을 넣지 않는다.

**기존 기준 충돌:** 02 §2.8의 기사 난이도 스테이지 제한은 5분이며 종자 8분·성기사 4분이다. 04의 스테이지 목표 8~12분 및 보스 첫 도전 3~5분과 그대로 양립한다고 볼 수 없다. 이 기획은 타이머를 변경하지 않는다. 보스 단독 그레이박스에서 목표를 계측한 뒤, 통합 검증에서 “보스 진입 잔여 시간 ≥ 실제 격파 시간”을 별도로 확인한다. 부족하면 해당 티켓을 완료 처리하지 않고 시간 기준의 정합성 문제를 기록한다. 입장 시 시간이 자동 초기화된다고 가정하지 않는다. GOAL의 8~15회는 S1 첫 클리어 시도 횟수이며 신규 보스의 확정 지표로 전용하지 않는다.

## S1 — 캐른: 구현 완료, 유지

시체 골렘을 재설계하지 않는다. `CAIRN.maxHp=300`, 본체 56×52px, 코어 10×10px이며 코어 1배·그 외 0.5배 피해다. 실제 페이즈 경계는 **HP 190(약 63.33%) / 90(30%)**이고 구간 HP는 110·100·90이다. 공통 60%·25%와 다른 M1-5 확정값을 유지한다.

P1은 `slam`(선행 30f·활성 12f·회복 36f·리치 40px)과 `throw`(선행 26f·포물선 2개·회복 30f), P2는 `quake`(선행 34f·낙석 3개·좀비 3마리·회복 40f), P3는 `split`(선행 30f·파편 4개·추적 240f)과 `merge`(36f)를 사용한다. 대기는 54f다. `chooseAttack`은 현재 페이즈의 후보를 `nextFloat`로 균등 추첨하며 연속 횟수를 저장하지 않는다. 가중치 순환이 구현되었다고 서술하지 않는다.

`damageCairn`은 코어·본체 AABB로 피해를 계산하고, 월드는 `slamBox`·`fragmentBoxes`·본체 접촉 및 방출 위험물로 플레이어 피격을 판정한다. `isCoreExposed`는 `split` 상태를 반환하지만 본체 피격·접촉 판정이 자동으로 코어 크기로 축소되지는 않는다. 격파 시 이 파일은 `state='dead'`·`killed=true`를 반환한다. 05에 적힌 400ms 히트스톱·화이트아웃 연출을 이 파일만으로 구현 완료라고 단정하지 않는다.

### 약점·격파·공정성·접근성

- **약점:** 앞가슴의 불씨 주머니. G5의 코어는 모든 상태에서 공격 가능하고 그 외 부위도 0.5배 피해를 받는다. E에서 외피가 벌어져 코어 위치가 더욱 잘 보인다. 특정 무기·각성·상단 공격을 요구하지 않는다.
- **격파 연출:** 턱이 벌어진 채 멎고 외피가 재로 떨어지며, 품고 있던 왕가 문장 조각이 드러난다. 신규 연출 제안으로 시간은 확정하지 않으며, 사망 즉시 모든 공격 판정을 끈다.
- **공정성 장치:** 최소 선행 48f, 방향 고정, C의 표식 고정, D의 일방향 진행, E의 조각별 예고. 전환 때 속도를 갑자기 높이지 않는다. 반격은 선행과 회복에서도 가능하다.
- **접근성 고려사항:** 불씨의 붉은색만으로 A/B/C를 구분하지 않고 턱·배·더듬이 실루엣을 달리한다. 바닥 표식은 불웅덩이 즉사 타일과 다른 끊어진 외곽선으로 표시한다. 섬광·열 왜곡을 줄여도 표식은 유지한다.
- **목표 시간:** 첫 도전 3~5분, 숙련 60~90초. 360 HP를 시작점으로, 숙련자는 B 틈에서 반격하고 E 코어를 연속 타격하는 차이로 시간을 줄인다. 너무 길면 선행 48f를 깎기 전에 이동 조각의 체류 시간과 코어 공격 기회를 조정하고 제안 표를 갱신한다.
- **밀도:** 잡몹 소환 0, C 최대 유해 상자 3개, E 조각 총 4개지만 동시 유해 1개. 다른 패턴의 잔여 위험물과 중첩하지 않는다.

### 스프라이트/파츠와 캐른 구조 대응 구현 메모

그레이박스 본체는 G5를 사용한다. 새로 그릴 부분은 개미의 머리·가슴·배와 더듬이·다리이며, 다리는 우선 장식 파츠로 둔다. `src/sprite/cairn.ts`의 행렬 조립·팔레트 방식은 재사용 후보지만 돌·뼈 도트를 개미 완성 에셋으로 간주하지 않는다. E용 외피 4개는 G6의 판정 파츠와 개별 대응한다. 초기 8MB 제한에 맞춰 해당 스테이지에서 지연 로드한다.

신규 `createAshmant / stepAshmant / damageAshmant`는 캐른처럼 불변 상태와 `{ boss, emission }` 반환을 사용한다. `phaseFor` 상당 함수는 216·90을 비교한다. A는 `slamBox`의 시간 구간과 방향별 배치를 따르고, B는 `stepThrow`의 비행 계산을 따르되 선행 시작 목표를 읽는다. C는 `stepQuake`의 세 위치를 재사용하지만 `rocks`를 방출하는 것만으로 바닥 분출이 되지는 않으므로 **새 바닥 공격 상자**가 필요하다. 좀비 방출은 없다.

- **약점:** 앞가슴 아래 독낭의 빛나는 마디. G5의 몸체/코어·피해 배율을 적용하며 수위가 높아야 드러나는 조건은 없다. 독안개 중에도 지상에서 일반 무기로 때릴 수 있다.
- **격파 연출:** 꼬리의 빛이 마디를 따라 꺼지고 집게가 벌어지며 독이 무해한 증기로 흩어진다. 실제 수위를 바꾸지 않는다. 신규 연출이며 사망 즉시 남은 독의 피해를 해제한다.
- **공정성 장치:** 독침은 한 지점을 예고하고 고정, 독안개는 외곽만 봉쇄, 둘은 절대로 동시 활성하지 않는다. 독 색상의 투척이 즉사나 지속 피해로 바뀌지 않는다. 약점 노출에 수위 상승이나 특정 무기가 필요하지 않다.

G5의 본체에 두 집게·등판·꼬리 마디·독낭을 새로 그린다. 꼬리 마디는 장식이고 A·D 활성 상자만 피해를 담당한다. 기존 캐른 팔 파츠의 합성 방식, 기존 `poison` 위험물의 24×16px·수명 180f는 재사용 후보다. 독안개 시각 자산이 전갈 전용 에셋으로 이미 준비되었다고 가정하지 않는다.

## 데이터 초안과 공통 구현 경계

`Stage`의 보스 관련 필드는 원래 `bossGateX`뿐이었다. **`bossKind`는 AF-3(선행 티켓)에서 구현됐다** — `src/game/stage.ts`, 종류 → 구현 연결은 `src/entities/bosses/registry.ts`, 렌더러는 `src/render/bossRenderers.ts`. JSON `id`와 같은 값을 쓴다. `bosses.json`의 `stage`와 TypeScript `Stage`는 별개 자료다. JSON에 행을 적는 것만으로 `createWorld`의 생성 종류가 바뀌지 않는다.

캐른 구조를 따른다는 말은 다음과 같은 범위를 뜻한다.

| 캐른의 실제 접점 | 신규 보스에서 필요한 대응 |
|---|---|
| `createCairn / awaken` | 생성·보스 게이트 진입 시 각 종류의 상태 생성/활성화 |
| `damageCairn / phaseFor` | 본체·코어 AABB와 HP로 다음 불변 상태 반환; HP 경계를 보스별로 비교 |
| `chooseAttack / stepIdle` | 호출 위치와 상태 전환 방식은 유지. 가중치 순환을 위한 `cycleIndex`는 신규 필드이며 캐른에는 현재 없음 |
| `stepTimed / stateFrames` | 선행·활성·회복을 틱으로 처리. 잔여 위험물이 있으면 타이머만으로 다음 패턴을 시작하지 않음 |
| `isWindingUp` | 그림·소리·바닥 표식이 같은 상태·틱을 읽음. E의 부분 예고도 표현 |
| `bodyBox / coreBox / slamBox / fragmentBoxes` | 피격 대상, 접촉 피해, 짧게 활성인 공격, 움직이는 파츠 판정을 분리 |
| `CairnContext {target, groundY}` | 목표 스냅샷·공격 방향 외에 회피 경계·가시 범위·잔여 위험물 확인 정보가 필요. 이는 현재 인터페이스 밖의 확장 제안 |
| `CairnEmission {gravestones, rocks, ghouls, quake}` | 기존 키의 의미를 바꾸지 않고 새 바닥 상자·독·마디 등의 연결을 보스 티켓에서 구현. `ghouls`는 신규 보스에서 비움 |
| 월드 방출물·접촉 처리 | 생성만 분기하지 말고 step·damage·피격 원인·위험물 소유·사망·재시작·클리어·렌더·HUD까지 종류에 맞게 연결 |

현재 위험물은 `kind`별 목록이며 보스 소유자 필드가 없다. 서로 다른 위험물의 종료 대기와 사망 정리를 위해 소유 정보를 추가하거나 동등하게 구분하는 방법이 필요하다. 이 역시 신규 구현 과제다. 본 문서는 해당 코드가 이미 존재한다고 주장하지 않는다. 특히 `world.ts`의 기존 `causeOfHit`은 본체 접촉을 별도로 검사하므로, 파츠를 분리해 그렸다는 이유로 플레이어가 본체를 통과할 수 있다고 가정해서는 안 된다.

## 티켓 분할안

이번 작업에서 Jira 티켓을 생성하거나 코드를 수정하지 않는다. 아래는 실행을 위한 분할 제안이다. **선행 티켓 1개가 아래 보스 4개 티켓 모두의 의존성**이다. 합계 5개이며, 각 티켓의 완료 조건은 3개로 제한한다.

### 선행 티켓 — 스테이지별 보스 슬롯: stage 데이터에 boss 종류 필드 추가 + world 가 종류별로 생성하도록 변경

> **구현됨 (AF-3)**: `Stage.bossKind` · `entities/bosses/{kind,slot,cairnSlot,registry}.ts` · `render/bossRenderers.ts`. 미등록 종류는 `BossNotRegisteredError`. 보스 티켓은 판정 한 줄(`registry.ts`) + 렌더러 한 줄(`bossRenderers.ts`)을 등록하고 `stageN.ts` 의 `bossKind` 를 바꾼다.

등록되지 않은 종류를 조용히 캐른으로 생성하지 않는 슬롯 구조를 먼저 만든다. 선행 작업 중 실제 콘텐츠 연결은 구현된 캐른을 유지하며, 신규 종류의 실제 S2~S5 활성화는 각 보스 티켓이 담당한다. 테스트용 생성 대역으로 분기를 검사하는 것은 제안이며 출시 콘텐츠로 취급하지 않는다.

완료 조건:

1. `Stage`에 보스 종류 필드(제안명 `bossKind`)와 종류별 생성 연결을 추가하고, 기존 스테이지의 캐른 동작은 유지한다. 서로 다른 등록 종류를 생성 대역으로 검증하며, 미등록 종류는 명시적으로 실패하고 캐른으로 대체되지 않는다.
2. 월드의 생성·활성화·갱신·피해·공격 상자·방출물·사망/재시작/결과와 렌더·HUD가 공통 접점을 통해 보스 종류를 처리한다. 신규 패턴 구현은 보스 티켓에 남기되, 방출물 소유 및 상한 때문에 예고만 실행되는 결함을 막을 연결 계약을 마련한다.
3. S1 캐른의 HP 300·경계 190/90·패턴·클리어와 기존 사거리/투척 검사가 유지된다. 다섯 스테이지의 진입·재시작·다음 판 진행 및 생성 분기 테스트가 통과하며 S1 재설계가 포함되지 않는다.
