# 동물 길건너 (minchan_5)

`minchan_1` 을 고급 스타일라이즈드 룩으로 다시 만든 것. 원본은 그대로 둔다.

빌드 스텝이 없다. `index.html` 을 열면 importmap 으로 three.js 를 CDN 에서 받고
`src/*.js` 를 ES 모듈로 직접 읽는다. Vercel 에는 정적 파일 그대로 올라간다.

## 왜 원본이 "투박"했나

지오메트리 문제가 절반도 안 됐다. 더 큰 원인은 **조명·톤매핑·애니메이션 부재**였다.
모델만 갈아끼우면 여전히 싸구려로 보인다. 그래서 세 가지를 함께 바꿨다.

| | 원본 | 여기 |
|---|---|---|
| 모델 | 전부 `BoxGeometry` 단색 | Quaternius CC0 리깅 모델 19종 |
| 머티리얼 | `MeshLambertMaterial` | `MeshStandardMaterial` + IBL |
| 톤매핑 | 없음 | ACESFilmic + 노출 |
| 애니메이션 | 없음 | 보행/질주/홉/사망 클립 |
| 구조 | 794줄 단일 HTML | 15개 모듈 |

## 구조

```
index.html          셸 · importmap · 로딩 UI · 오버레이
src/
  constants.js      튜닝값. 원본과 수치를 맞춰야 하는 값은 근거를 주석에
  rng.js            결정론적 난수 (줄 번호 → 항상 같은 줄)
  rowplan.js        한 줄에 무엇이 있는지 — three.js 를 모르는 순수 로직
  biomes.js         바이오미 진행 · 색 보간
  roster.js         동물 19종 정의 + 바이오미 편성
  jump.js           점프 포물선 (수식)
  collision.js      AABB 겹침 (순수 함수)
  assets.js         GLB 로딩 · 스케일 역산 · 머티리얼 보정
  pool.js           종별 오브젝트 풀 (SkeletonUtils.clone)
  world.js          줄 메쉬 생성/제거 · 장식물
  animals.js        개체 이동 · 보행 클립 선택
  player.js         닭 · 격자 이동 · 사망 연출
  renderer.js       렌더러 · 조명 · 섀도맵 추적
  ui.js             DOM · 입력
  main.js           게임 루프
```

`rowplan` · `biomes` · `jump` · `collision` · `rng` 은 three.js 를 import 하지 않는다.
그래서 브라우저 없이 테스트할 수 있다.

## 원본에서 고친 것

1. **GPU 메모리 누수** — 원본 `removeRow()` 는 `dispose()` 없이 `scene.remove()` 만 했다.
   여기서는 "지울 때 dispose 하자" 대신 **줄마다 새로 만들지 않는다** 로 풀었다.
   지오메트리는 전역 공유, 머티리얼은 색으로 캐시. 반납할 자원이 없으니 샐 것도 없다.
   추가로 유휴 개체 풀에 상한(종당 8)을 뒀다 — 없으면 "한 화면에 같은 종이 몇 마리나
   겹쳤나"의 최고 기록이 갱신될 때마다 개체가 영구히 늘고, 개체 하나가 SkinnedMesh
   4~8개와 그만큼의 본 텍스처를 문다. 20,000줄 주행에서 지오메트리·텍스처가 평탄하다.
2. **생성 거리와 시야 거리 불일치** — 원본은 `GEN_AHEAD=35` 인데 안개 `far=28` 이라
   보이지도 않는 줄을 스폰하고 애니메이션까지 돌렸다. 반대로 생성이 안개보다 가까우면
   월드의 끝이 그대로 드러난다. 양쪽 다 막도록 `GEN_AHEAD = MAX_FOG_FAR - 카메라 오프셋`
   으로 묶고 테스트로 강제한다.
3. **섀도맵 낭비** — `±14` 고정을 플레이어 주변 `±8` 추적으로. 같은 해상도에 텍셀 밀도가 오른다.
4. **사망 연출** — 납작하게 눌리고 빨개지는 연출은 스타일라이즈드에 안 맞는다.
   맞은 방향으로 튕겨나가며 구르고, 카메라 흔들림 + 슬로모가 붙는다.
5. **바닥 폭 불일치** — 바닥 40 / 오버레이 9 로 이음매가 보였다. 바닥은 한 색으로 깔고
   좌우 대칭 갓길로 경계를 표시한다.
6. **물리 엔진 제거** — cannon-es 에서 실제로 쓰인 건 점프 포물선과 AABB 겹침 둘뿐이었다.
   게다가 `beginContact` 는 고속 개체(뱀)를 프레임 타이밍에 따라 놓칠 수 있었다.
   수식 + 매 프레임 AABB 로 바꾸니 원본과 수치는 같으면서 결정론적이다.

## 테스트

```bash
# 순수 로직 (브라우저 불필요) — 32개
node --test 'tests/*.test.mjs'

# 브라우저 전 구간 (로딩 → 시작 → 이동 → 사망 → 재시작) — 8개
cd tools && npm install && npx playwright install chromium --only-shell && npm run e2e
```

3D 렌더에 커버리지 80% 를 강제하는 건 비현실적이라 순수 로직만 유닛 테스트하고,
화면은 E2E 에서 "실제로 그려졌는가 · 바이오미별 색조가 의도한 방향인가"로 본다.
픽셀 단위 비교는 GPU·드라이버가 다르면 그냥 깨진다.
